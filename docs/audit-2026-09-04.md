# App audit — September 4, 2026

The priority was a dependable accountability app for five friends: clear promises,
photo proof, fair reviews, working invitations, and comfortable phone use. Changes
are implemented locally. Nothing has been deployed or pushed.

## Data boundary

No existing dev, test, or production records were changed. No schema changes or new
migrations were needed. All behavioral tests used fresh Docker Postgres containers
with fictional friends, tasks, sessions, and generated images; the runner removes
only containers it creates. External AI and push credentials were blank during tests.

Local Prisma commands now explicitly read the local `.env` and reject remote targets
outside Vercel. This closes a real tooling hazard: Bun can auto-load the production
backup. The temporary browser runner supplies and validates its own loopback database.
Two checks confirmed that injected remote URLs cannot replace the local target and
that an explicit remote test target is rejected before Prisma starts validation.

## Findings and implemented changes

| Area | Problems addressed | Result |
| --- | --- | --- |
| Task and verdict integrity | Submitted promises could be rewritten; competing writes lacked a consistent retry policy | Proof fixes the promise text; serializable transactions retry conflicts and return useful 409 responses; one competing verdict wins |
| Daily use | Older unfinished tasks disappeared from Today; countdown never detected rollover; refreshed props left stale client state | Earlier work remains available for late proof; Phoenix rollover refreshes; server changes reach task, verdict, reply, and check-in state |
| Friend activity | No routine refresh; cross-circle client state could survive switching | Visible boards refresh every 15 seconds, pause around active forms, expose manual refresh and offline status, and reset state across circles |
| Photo proof | Large phone photos exceeded the host request limit; weak file feedback; dialogs could close mid-save | Client resizing, preview, a 20 MB source limit and 4 MB prepared limit, bounded multipart reads, useful errors, and pending-state protection; server still decodes, strips metadata and stores WebP |
| Proof review | Missing definition of done; truncated descriptions; old notifications opened the wrong screen | Full promise context, reviewable historical pending proof, targeted tabs/day/circle, and explicit links back to current activity |
| AI assistance | Duplicated background code, stuck pending reads, retry buttons that stayed disabled, non-atomic limits | Shared assessment runner, recoverable retries, per-proof retry limits and atomic hourly budgets; safe error logging; friends remain the decision makers |
| Authentication and circles | Returning Discord users did not redeem invites; circle-name equality confused membership; active circle button was a dead end | Callback redemption handles new and returning sessions, membership uses IDs, expired claims show recovery, and current-circle navigation works |
| Invitations | Revocation could race redemption; existing membership could be overwritten | Final redemption checks revocation and expiration inside the transaction; existing roles are preserved; one link admits one new member |
| Request protection | Circle mutations lacked origin checks; malformed dates/cookies could crash; JSON bodies were buffered before limits; push endpoints accepted arbitrary hosts | Same-origin mutation checks, safe parsing, streaming byte limits, shared action limits, and browser push-service allowlist |
| Notifications | Task/check-in preference switches had no effect; read states could lie; menu semantics were inappropriate; timestamp pagination skipped ties | Optional fan-out is wired, saves/read actions check responses, bell uses a popover with tabs, and stable pagination handles simultaneous events |
| Privacy and push | Private invite activity appeared in shared feed; browser-only subscription state did not reflect account ownership | Private invite events are excluded; notification destinations stay in-app; push ownership is checked and device push is disconnected on sign-out; private images require revalidation |
| Replies | The oldest 50 messages loaded forever, hiding new ones | Newest messages load first, render chronologically, and earlier replies can be loaded with a circle-scoped cursor |
| Weekly reports | Wide table editor was awkward on phones; reload lost edits; cross-week proof was omitted | Responsive row cards, local drafts per user/circle/week, boundary-overlap queries, stable rows for replacement proof, validation, and status refresh without changing original work |
| PDF | Very short and heavily overlapping blocks could draw text outside their bounds | True-duration blocks and bounded labels; crowded/short labels may be omitted with an explicit legend; overnight entries identify both days |
| CSS and accessibility | Mobile hydration failure, nested main elements, invalid list roles, weak contrast, small touch targets, card alignment and dialog spacing problems | Fixed streaming boundary, landmarks and review lists, darker warning/tab text, touch sizing, wrapping, card container queries, date controls, and dialog spacing |
| App shell | Sidebar stayed open after navigation; stale announcement; restrictive orientation/text selection; old error recovery API | Navigation closes the phone sidebar, landscape and text selection work, stale banner is removed, error retry uses the installed Next API, and changelog math CSS stays on that page |
| Operations | Large reconciliation transactions and successful HTTP status after failed circles | Small batches, bounded transaction retries, idempotent missed-task events, and failure status when a circle fails |
| Tooling | README described nonexistent browser tests; deprecated middleware convention; vulnerable indirect dependencies | Reproducible Docker/Playwright suite, current Next proxy convention, corrected setup docs, updated Lodash and documented dependency overrides |

Every user-facing change is recorded in `lib/changelog.ts`.

## Verification

- Unit tests cover task policy, Phoenix time boundaries, invalid dates, schemas,
  injection instructions, payload byte limits/cancellation, malformed cookies,
  internal destinations, push allowlists, draft corruption, and PDF structure.
- Browser tests cover all seven main pages at 320, 390, 768, and 1440 pixels,
  including touch contexts on phone widths and captured runtime errors.
- Automated accessibility checks cover public and member screens, notification
  settings, and upload-dialog errors. Automated checks are not a complete manual
  screen-reader or accessibility certification.
- Behavioral tests exercise cross-circle access, owner-only actions, origin
  rejection, uploads and conflicting verdicts, immutable promises, late proof,
  invitation races, deep links, refresh/drafts, settings and notification delivery,
  long threads, reply ownership, check-ins, atomic request limits, and cron retries.
- Fake-data production build, Prisma generation and validation, disposable migration
  deployment, TypeScript, Biome, and the repository UI composition audit pass.
- Rendered and visually inspected both PDF pages with 30 entries, overlaps,
  overnight work, and a one-minute task. Inspected phone and desktop screenshots.
- Dependency audit: **zero reported advisories** after checking 663 packages.

## Dependency decisions

Lodash updated from 4.17.21 to 4.18.0 within its supported range. Prisma 7.10.0 pins
older `mysql2` and `deepmerge-ts`, so package overrides select 3.24.3 and 8.0.2.
The app uses Postgres, not MySQL. Deepmerge is used to load this plain-object Prisma
configuration; the v8 Map behavior change is not exercised here. Generation,
validation, migrations and production compilation were verified with the overrides.
Remove them when Prisma updates its pins; do not jump to a Prisma release candidate
just to clear a dependency report.

## Limits and deliberate tradeoffs

1. **Live integrations remain unverified.** Discord callback code was reviewed
   against the installed Better Auth implementation, but no real Discord identity
   was signed in. No paid AI request or real device push was sent. Those need a live
   smoke test after deployment with the actual credentials and callback URLs.
2. **Browser coverage is Chromium.** Phone widths and touch are exercised, but real
   iOS Safari, Android camera pickers, HEIC decoding, PWA installation, and background
   notifications still need device checks. Unsupported HEIC decoding gives a useful
   export/smaller-file message rather than pretending all devices can handle it.
3. **Fan-out uses Next `after`, not a durable outbox.** The task/proof write commits
   before notification/AI work. An interrupted function can miss a notification;
   proof reads can be retried. A durable queue/outbox would require a separate schema
   and delivery design; for five friends this is a documented operational tradeoff.
4. **History is retained.** Photos remain in Postgres and there is no automatic purge.
   Storage growth and production backups were not changed or independently verified.
   The PDF is limited to 56 entries; dense schedules use the numbered task list when
   labels cannot fit. The squad queue shows 20 pending items needing your vote at a time and advances
   as they are reviewed; individual notification links still reach their target.
5. **Local report drafts are device-local.** They do not sync to another browser.
   They are namespaced by account, circle, and week and do not edit task/proof records.
6. **No deployment was performed.** Existing records are not retroactively repaired.
   New rules apply when this version runs; review and deploy through the normal flow.
